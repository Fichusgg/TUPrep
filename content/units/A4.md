## Key ideas

- **Linear search**: up to $n$ comparisons. **Binary search** (sorted input only): at most $\lfloor\log_2 n\rfloor+1$ inspections.
- **Bubble sort**: after pass $k$, the $k$ largest elements are in place at the end. Total swaps = number of inverted pairs.
- **Selection sort**: swaps the minimum of the unsorted part to its front. **Insertion sort**: inserts each element into the sorted prefix (fast on nearly sorted data). **Merge sort**: halve, sort, merge — $O(n\log n)$.
- **Recursion**: always identify the base case; evaluate bottom-up when possible; draw the call tree to count calls.
- **Growth rates** from slow to fast: $1,\ \log n,\ n,\ n\log n,\ n^2,\ 2^n,\ n!$. Constants and lower-order terms do not change the class.
- Doubling the input of an $O(n^2)$ algorithm roughly quadruples the time; of an $O(\log n)$ algorithm it adds a constant.

## Common traps

- Running binary search on unsorted data in your head.
- Counting comparisons and swaps as the same thing.
- Missing a base case and "computing" a recursion that never terminates.
- Concluding that an algorithm with a smaller constant is always faster.
